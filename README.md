# Telecom KPI Monitor

A 4G LTE / 5G NR network KPI and alarm monitoring dashboard, laid out the way a NOC (Network Operations Centre) console is: KPI overview, per-cell KPI trends, an alarm / fault log and Wireshark-style packet statistics. All data is synthetic.

**Status: scaffold.** The app shell, routing, data model and page placeholders exist; the features below are specified in [PLAN.md](./PLAN.md) and are being built milestone by milestone.

Live scaffold: https://telecom-kpi-monitor.vercel.app

## What it will do (per PLAN.md)

| View | Purpose |
| --- | --- |
| Overview | KPI cards (call drop rate, RRC setup success, DL/UL throughput, latency, PRB utilization), active alarm counts by severity, worst-cell list |
| KPIs | Time-series per cell / site / technology with configurable thresholds and breach markers; CSV export for network performance reports |
| Alarms | NOC-style alarm and fault tracking: severity, probable cause, state (active / acknowledged / cleared), correlation with KPI degradation |
| Packets | Protocol hierarchy, top conversations and TCP retransmission summary from a JSON export of a `.pcap` (tshark) |

## Tech stack

- Vite 5 + React 18 + TypeScript
- Charts: Recharts (planned, M2)
- Data: synthetic JSON generated by `scripts/generate-synthetic-data.mjs` from a fixed seed (M1)
- Hosting: Vercel

## Getting started

```bash
npm install
npm run dev       # http://localhost:5173
npm run build     # type-check + production build to dist/
npm run gen:data  # synthetic dataset (stub until M1)
```

## KPI definitions used

- **Call drop rate (CDR)** = dropped calls / (dropped + completed calls) x 100
- **RRC setup success rate** = successful RRC connection setups / attempts x 100
- **Handover success rate** = successful handovers / attempts x 100
- **PRB utilization** = used physical resource blocks / available PRBs x 100 (congestion indicator)
- **Latency** = user-plane round-trip time in ms
- **Throughput** = DL / UL MAC-layer throughput in Mbps
